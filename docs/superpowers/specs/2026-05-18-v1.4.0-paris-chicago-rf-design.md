## 1. Problem Statement

Paris and Chicago currently have no city-specific Random Forest models in the FastAPI
serving stack. Both cities fall back to the Seoul artifact in `services/predictor.py`
(`_FALLBACK_CITY = "seoul"`), which reduces prediction accuracy because Seoul's demand
patterns (TEMPERATURE-dominant, RMSE 173 bikes/hr) differ from European and Midwestern
cycling behaviour.

This spec covers sourcing trip + weather data for both cities, normalising to Seoul
schema, training RF artifacts, and verifying FastAPI auto-routes to the new models.

## 3. Data Sources

### Paris

| Property | Value |
|---|---|
| Source | opendata.paris.fr — "Comptage vélo - Données compteurs" |
| Download URL | `https://opendata.paris.fr/explore/dataset/comptage-velo-donnees-compteurs/` |
| File | `comptage-velo-donnees-compteurs.csv` |
| Coverage | 2016–present (use 2019–2022 filter) |
| Demand signal | Hourly cyclist counts at 60+ permanent city counters summed per hour |
| Auth required | None — public CSV download |
| Manual step | User downloads CSV → places at `data/raw/paris/paris_hourly.csv` |

**Key columns in source:**
- `Date et heure de comptage` — ISO datetime string (parse to DATE + HOUR)
- `Comptage horaire` — integer count of cyclists at one counter for that hour

Hourly demand = `SUM(Comptage horaire)` across all counters for each (DATE, HOUR).

### Chicago

| Property | Value |
|---|---|
| Source | Divvy system data — divvybikes.com/system-data |
| File format | Quarterly CSV zips, 2019–2022 |
| Demand signal | Individual trip starts; aggregate to hourly count |
| Auth required | None — public download |
| Manual step | User downloads 2019–2022 zip files → extracts all CSVs into `data/raw/chicago/trips/` |

**Key column in source:**
- `started_at` — ISO datetime `YYYY-MM-DD HH:MM:SS` (new Divvy format, same as DC)

Hourly demand = COUNT of trips with `started_at` in each (DATE, HOUR) bucket.

### Weather (both cities)

Open-Meteo Historical Weather API — same endpoint and variables used for DC and NYC:

| Variable | Seoul schema column |
|---|---|
| `temperature_2m` | `TEMPERATURE` (°C) |
| `relative_humidity_2m` | `HUMIDITY` (int %) |
| `wind_speed_10m` | `WIND_SPEED` (m/s) |
| `visibility` ÷ 10 | `VISIBILITY` (10m units, int) |
| `dew_point_2m` | `DEW_POINT_TEMPERATURE` (°C) |
| `precipitation` | `RAINFALL` (mm) |
| `snowfall` | `SNOWFALL` (cm) |
| — | `SOLAR_RADIATION = 0.0` (not free-tier) |

| City | Lat | Lng | Date range |
|---|---|---|---|
| Paris | 48.8566 | 2.3522 | 2019-01-01 → 2022-12-31 |
| Chicago | 41.8781 | -87.6298 | 2019-01-01 → 2022-12-31 |

## 5. Script Design

### `data/fetch_paris_weather.py`

Mirrors `data/fetch_dc_weather.py` structure exactly:

```
Step 1 — Load data/raw/paris/paris_hourly.csv
         Filter rows to 2019-01-01 → 2022-12-31
         Parse "Date et heure de comptage" → DATE (DD/MM/YYYY) + HOUR (int)
         Aggregate: GROUP BY DATE, HOUR → SUM(Comptage horaire) AS RENTED_BIKE_COUNT
         Save → data/raw/paris/paris_trips_hourly.csv

Step 2 — Fetch Open-Meteo historical weather for Paris
         lat=48.8566, lng=2.3522, start=2019-01-01, end=2022-12-31
         Request variables: temperature_2m, relative_humidity_2m, wind_speed_10m,
                            precipitation, snowfall, visibility, dew_point_2m
         Resample to hourly if sub-hourly returned
         Save → data/raw/paris/paris_weather.csv

Step 3 — Join trips + weather on DATE + HOUR (inner join; drops unmatched rows)
         Save → data/raw/paris/paris_joined.csv

Step 4 — Call prepare_paris_from_joined("data/raw/paris/paris_joined.csv")
         Save result → data/processed/paris_bike_sharing.csv

Print row count and head(5) to confirm output schema.
```

### `data/fetch_chicago_weather.py`

Copy of `data/fetch_dc_weather.py` with Chicago coordinates and Divvy column name:

```
Step 1 — Glob data/raw/chicago/trips/*.csv
         Abort with FileNotFoundError if no CSVs found (same guard as DC script)
         Parse started_at → DATE (DD/MM/YYYY) + HOUR (int)
         Aggregate: GROUP BY DATE, HOUR → COUNT(*) AS RENTED_BIKE_COUNT
         Save → data/raw/chicago/chicago_trips_hourly.csv

Step 2 — Fetch Open-Meteo historical weather for Chicago
         lat=41.8781, lng=-87.6298, start=2019-01-01, end=2022-12-31
         Same variables as Paris
         Save → data/raw/chicago/chicago_weather.csv

Step 3 — Join trips + weather on DATE + HOUR
         Save → data/raw/chicago/chicago_joined.csv

Step 4 — Call prepare_chicago_from_joined("data/raw/chicago/chicago_joined.csv")
         Save result → data/processed/chicago_bike_sharing.csv

Print row count and head(5) to confirm output schema.
```

### `data/prepare_city_data.py` additions

Append two functions following the existing `prepare_dc_from_joined()` pattern:

**`prepare_paris_from_joined(path)`**
- Input: paris_joined.csv (DATE DD/MM/YYYY, HOUR int, RENTED_BIKE_COUNT int, Open-Meteo columns)
- Column mapping: identical to `prepare_dc_from_joined()` — same Open-Meteo column names, same units
- SEASONS: derived from month via `pd.cut()` (same bins as DC/NYC)
- HOLIDAY: `"No Holiday"` — no French holiday calendar loaded
- FUNCTIONING_DAY: `"Yes"` — Vélib' operates year-round
- Returns Seoul-schema DataFrame

**`prepare_chicago_from_joined(path)`**
- Input: chicago_joined.csv (same structure as paris_joined.csv)
- Column mapping: identical to `prepare_dc_from_joined()`
- SEASONS: same `pd.cut()` derivation (Northern Hemisphere bins match Chicago)
- HOLIDAY: `"No Holiday"`
- FUNCTIONING_DAY: `"Yes"`
- Returns Seoul-schema DataFrame

Both functions select and return the 14 Seoul-schema columns in the canonical order.

## 6. Training Commands

Run from the `bike-demand-ml-system` repo root after both processed CSVs exist:

```bash
# Paris
python -m models.train \
  --city paris \
  --data data/processed/paris_bike_sharing.csv \
  --n-estimators 100 \
  --random-state 42

# Chicago
python -m models.train \
  --city chicago \
  --data data/processed/chicago_bike_sharing.csv \
  --n-estimators 100 \
  --random-state 42
```

Expected outputs per city:
- `models/artifacts/<city>/random_forest_model.pkl`
- `models/artifacts/<city>/feature_columns.pkl`
- Console: train/test row counts, RMSE, MAE, top-10 feature importances

## 8. Error Handling

Both fetch scripts follow the same error-handling contract as `fetch_dc_weather.py`:

| Failure | Handling |
|---|---|
| No trip CSVs in `trips/` directory | `FileNotFoundError` with human-readable download instructions |
| paris_hourly.csv not found | `FileNotFoundError` with download URL in message |
| Open-Meteo HTTP error | `requests.raise_for_status()` — surfaces HTTP status and message |
| Inner join returns 0 rows | `ValueError` with diagnostic print of trip and weather date ranges |
| Training on empty CSV | `train.py` will raise via `scikit-learn` naturally — no special handling needed |

## 12. Known Risks

| Risk | Mitigation |
|---|---|
| Paris counter data measures all cyclists, not just Vélib' rentals — absolute scale differs from station-rental cities | RF learns relative patterns (hour, season, temperature); scale difference affects RMSE magnitude but not model validity for demand forecasting |
| Divvy CSVs changed column format across years (pre-2020 used "start_time", post-2020 uses "started_at") | fetch_chicago_weather.py tries both column names (same guard pattern as fetch_dc_weather.py) |
| Open-Meteo free API rate limit (~10,000 req/day) | Single batch request per city for full date range — well within limit |
| Paris hourly.csv may have missing hours (counter maintenance gaps) | Inner join with weather drops unmatched rows; final row count may be < 35,000 — acceptable |
